# Shared layout, home and catalog — implementation plan

> **Status:** done. Translated to English on 2026-11-19. The pages later moved from `app/` to the `app/(browse)/` route group (product page plan); the paths below are the ones from the time.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Have the home (`/`) and the catalog (`/catalogo`) working against the API, with the structure shared by all screens: header, tabs, footer, cookie notice, prices and error handling.

**Architecture:** Pages in `app/` only fetch data and compose. Logic lives in `src/`: `lib/` (environment, API client, formatting), `components/` (primitives and store frame) and `features/` (`catalog`, `privacy`). Filters and sort live in the page address and are sent by `<Form>` from `next/form`, with no custom JavaScript. In the tests, the real API is replaced by a fake API with fixed data.

**Tech Stack:** Next.js 16.4.6 (App Router), React 19, Tailwind 4, Zod 4, `server-only`, types generated by `openapi-typescript`, `node:test` for logic and Playwright for screens.

**Spec:** `docs/SPEC-CLIENT.md` (sections 3, 4 and 5), `docs/DESIGN.md`, `contract/openapi.yaml`, `docs/GLOSSARY.md`.

## Global constraints

- Code in plain English, names from `docs/GLOSSARY.md`; visible text in Portuguese; store routes in Portuguese.
- Colors only through the tokens (`background`, `surface`, `card`, `primary`, `muted`, `control`, `line`, `sale`, `success`, `error`). `sale` never on a button or link. No shadow, no `dark:`.
- Controls as pills (`rounded-control`); photos and cards with square corners. 48×48px touch target with 8px between targets.
- Headings `font-serif` weight 400; body and prices `font-sans`; labels `font-mono` uppercase with `tracking-[0.08em]`.
- Server component by default; `"use client"` only where there is an event or state. No `"use client"` is planned in this plan.
- Files that talk to the API start with `import "server-only"`. A component never gets the whole API response.
- Before using a Next API, read the guide in `node_modules/next/dist/docs/` (`form.md`, `link.md`, `cookies.md`, `image.md`, Server Actions).
- `.ts` files tested by `node:test` use relative imports with the `.ts` extension (`node` doesn't understand `@/`).
- Money travels in cents; the screen shows `R$ 1.234,56`.
- Commits are the owner's: each "Commit" step means leaving the files ready and suggesting the message (in Portuguese).

## Review focus

1. **API down or slow:** home and catalog show the error message with "Tentar de novo" and the filters stay in the address. Tested in Task 2 (API client) and Task 8 (screen).
2. **Address typed by hand with an odd value** (`?ordem=xyz`, `?precoMin=abc`, `?categoria=sapatos`, `?pagina=-1`): the invalid value is ignored and the page opens normally, never with a 500 error. Tested in Task 5.
3. **Repeated parameter** (`?tamanho=M&tamanho=G`): the first one wins. Tested in Task 5.
4. **Reject cookies and keep browsing:** the store keeps working and the notice doesn't come back. Tested in Task 4.
5. **Long text** (long product name, 80-character search): text wraps and is never cut. Tested in Task 6, with the fake API's long name.

## Not in this plan

- `CAT-08` (quick buy) and the item count on the Sacola tab (`GER-01`): they depend on the bag, which comes in the next plan.
- `GER-02` and the purchase part of `GER-04`: they apply to product, bag and checkout, which don't exist yet.
- Product, bag and account screens: the links to `/produto/[slug]`, `/sacola` and `/conta` already exist, but lead to the 404 page until then.

## Decisions in this plan

| Subject | Decision |
|---|---|
| Catalog address parameters (customer sees them, so Portuguese) | `categoria`, `tamanho`, `cor`, `precoMin`, `precoMax`, `busca`, `ordem`, `pagina` |
| Categories in the address | `camisetas`, `calcas`, `jaquetas`, `acessorios` → API `tshirts`, `pants`, `jackets`, `accessories` |
| Sort in the address | `novidades` (default, left out of the address), `menor-preco`, `maior-preco`, `maior-desconto`, `mais-vendidos` → API `newest`, `lowest_price`, `highest_price`, `biggest_discount`, `best_sellers` |
| Price in the address | whole reais (`precoMin=200`); the API gets cents (`20000`) |
| Consent cookie | `helena_consent`, JSON `{"v":1,"analytics":bool,"marketing":bool}`, `httpOnly`, `SameSite=Lax`, `Secure` in production, valid for 180 days |
| Search | route `/buscar`, a form that submits to `/catalogo?busca=` |
| API timeout | 5 seconds; after that it counts as a failure (`GER-06`) |
| Screen tests | Playwright, Chromium only, at phone size (Pixel 7) |
