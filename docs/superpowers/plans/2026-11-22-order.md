> **Status:** approved by the owner on 2026-11-22; **all 4 tasks done and committed by 2026-11-23** (last: `8a69c43`). Plan A as before: tasks run inline, one at a time; finish a task, report, stop and wait for the go-ahead. > **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/pedido/[numero]` as the confirmation right after payment (green check, back to the home page by itself) and as tracking afterwards, plus the lookup by number + e-mail at `/pedido`.

**Architecture:** A new `orders` domain. One server page reads the order with an access cookie (`helena_order` during the purchase, the new `helena_tracking` after it) and composes either the confirmation (`?confirmado=1`) or the tracking view; a pure `views.ts` turns the API order into texts. The payment flow redirects to the confirmation, whose client leaf calls checkout's `finishPurchase` (moves the access to `helena_tracking`, forgets the bag) and goes home after 8 s without interaction. The lookup is one Server Action against `POST /v1/orders/access`.

**Tech Stack:** Next.js 16.4.6 (App Router, `cacheComponents`), React 19, Tailwind 4, Zod 4, `server-only`, `openapi-typescript` types, `node:test`, Playwright. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-22-order-design.md` (design), `docs/SPEC-CLIENT.md` section 9 (`PED-01` to `PED-08`) and `CHK-16`, `CHK-20`; `contract/openapi.yaml` (`getOrder`, `accessOrderWithoutAccount`, schemas `Order`, `OrderStep`, `OrderAccess`, `OrderStatus`); `docs/GLOSSARY.md`.

## Global Constraints

- Everything in `CLAUDE.md` and in the checkout plan's global constraints (`2026-11-20-checkout.md`) still applies.
- **Contract:** no change. `npm run types` leaves `src/lib/api-types.ts` unchanged.
- **Authorization:** the order is read only with an access from her own `httpOnly` cookie whose `number` equals the URL's number, sent as `X-Order-Access`. The URL number alone never shows data; no access, a different number, 401 or 404 → the lookup form with the number filled in.
- **Tracking cookie:** name `helena_tracking`, value `JSON.stringify({ number, access })`, `httpOnly`, `secure` in production, `sameSite: "lax"`, `path: "/"`; `maxAge` 3600 after a payment, or the seconds until the lookup's `expiresAt` (at least 60). Written only from Server Actions.
- **Never on these screens:** CPF, phone, full address (`PED-05`). `delivery.address` is never read.
- **Store URLs** (glossary): `/pedido` → `OrderLookupPage`, `/pedido/[numero]` → `OrderPage`, `?confirmado=1` → `confirmed`. `?pedido=` is removed.
- **Exact screen texts:** "Pedido confirmado", "Pedido {número}", "Enviamos os detalhes para {e-mail mascarado}", "Forma de pagamento", "PIX", "Cartão de crédito · {n}x", "Acompanhar pedido", "Continuar comprando", "Pagamento confirmado", "Em separação", "Enviado", "Entregue", "Etapa atual: {etapa}", "Código de rastreio", "Copiar código", "Código copiado", "Rastrear entrega", "Entrega em {cidade}/{UF}", "Suporte em andamento", "Solicitar devolução", "Número do pedido", "E-mail", "Ver pedido", "Não encontramos um pedido com esses dados", "Campo obrigatório", "Digite um e-mail válido", "Confira o número do pedido".
- **Dates:** step dates as `dd/mm` in `America/Sao_Paulo` (`Intl.DateTimeFormat("pt-BR", { day: "2-digit", month: "2-digit", timeZone: "America/Sao_Paulo" })`).
- **Design:** the check is `CheckIcon` in `text-success`, at least 64px, with "Pedido confirmado" as the page's `h1` right under it; no animation (so nothing to turn off for `prefers-reduced-motion`). Tokens only, 48px targets, focus visible.

## Review Focus

1. **A made-up or someone else's `/pedido/HL-…` (with or without `?confirmado=1`):** only the lookup form, with no order data. Tested in Task 2.
2. **She reads the confirmation with a screen reader or starts to tap:** any `pointerdown`, `keydown`, `touchstart`, `wheel` or `focusin` cancels the return; no focus is moved by code (that would fire `focusin`). Tested in Task 2 (a key press and a tap).
3. **She reloads the confirmation after the cookies moved:** the page reads the order with `helena_tracking` and still shows it. Tested in Task 2.
4. **A lookup during a new checkout:** it writes only `helena_tracking`; the payment in progress (`helena_order`) is untouched. Tested in Task 4.
5. **Lookup with spaces or lowercase (" hl-100482 ", "MARIA@Exemplo.com"):** trimmed, number uppercased, e-mail lowercased before the call. Tested in Task 4.
