**Goal:** Steps 2 and 3 of the purchase working against the API: `/checkout` (details and delivery, `CHK-01` to `CHK-13`, `CHK-23`), `/checkout/pagamento` (PIX and card with a simulated gateway, `CHK-12` to `CHK-22`), the success message on the home page, and the reservation timer on the bag (`SAC-17`).

**Architecture:** A new `checkout` domain. `/checkout` is a server page that reads the bag (cart domain) and composes one client form; the form validates with the same Zod schema the server uses, saves the lead through a Server Action when every required field is valid (`CHK-05`), and keeps what she typed in `sessionStorage` (`CHK-23`). "Ir para pagamento" validates again on the server, saves the details, creates the order and keeps `{ number, access }` in an `httpOnly` order cookie. `/checkout/pagamento` reads the order with that cookie and composes the timer, the summary and one client payment leaf; PIX polls a Server Action, the card goes through a simulated gateway component whose fields never reach the server. A paid order sends her to `/?pedido=HL-…`, where the home page shows the success box only if the order cookie matches and the API says it is paid.

**Tech Stack:** Next.js 16.4.6 (App Router, `cacheComponents` on), React 19 (`useActionState`), Tailwind 4, Zod 4, `server-only`, types from `openapi-typescript`, `node:test` and Playwright. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-20-checkout-design.md` (the design, approved by the owner's commit `811cc19`), `docs/SPEC-CLIENT.md` (section 2, `CHK-01` to `CHK-23`, `SAC-07`, `SAC-17`, `GER-02`, `GER-06`, `GER-07`), `contract/openapi.yaml` (`saveCustomerDetails`, `createOrder`, `getOrder`, `payOrder`, schemas `CustomerDetails`, `Address`, `Order`, `CreatedOrder`, `Payment`, `NewPayment`), `docs/GLOSSARY.md`. ## Global constraints

Everything in `CLAUDE.md` and in the bag plan's global constraints (`2026-11-19-bag.md`). In addition:

- **Contract:** no change except one documentation sentence in `createOrder`'s `description` (Task 1). `npm run types` must leave `src/lib/api-types.ts` unchanged.
- **Card data:** the simulated gateway's inputs have **no `name` attribute** and sit **outside any `<form>`**; only `cardToken` (`tok_test_` + last 4 digits) and `installments` go to the Server Action. Nothing about the card goes into `sessionStorage`, state sent to the server, or logs.
- **Authorization in every action and query:** the cart id only from `readCartId()`; the order only from the order cookie (`readOrderAccess()`), sent as `X-Order-Access`. An order number from a URL or form is never trusted alone.
- **Server Action order:** authorization → Zod → API call → `refresh()` only after a change that worked.
- **Idempotency:** each attempt (`createOrder`, `payOrder`) carries an `Idempotency-Key` created in the browser with `crypto.randomUUID()` when the button becomes ready, sent in a hidden input, validated with `z.uuid()`, renewed after each answer.
- **Amounts never recalculated in the front end** except the per-installment text `Nx de R$ X` (`CHK-19`), which divides the order `total` by `n` and rounds down to the cent.
- **Order cookie:** name `helena_order`, value `JSON.stringify({ number, access })`, `httpOnly`, `secure` in production, `sameSite: "lax"`, `path: "/"`, `maxAge` 3600.

## Review focus

1. **She reloads `/checkout/pagamento` or opens it in a new tab:** the page rebuilds from the order cookie (timer from the order's `reservationExpiresAt`, the PIX code from `order.payment.pix` when still pending), never asks to pay twice. Tested in Task 5.
2. **A made-up or someone else's `/?pedido=HL-…`:** no cookie, a different number, or an order not paid → the home page shows nothing extra and no data. Tested in Task 5.
3. **The lead save fails (500) while she types:** nothing shows on screen and typing goes on; "Ir para pagamento" saves again and, if it fails there, shows the `GER-06` message above the bar with everything still filled in. Tested in Task 3.
4. **Two taps on "Ir para pagamento" or on "Pagar":** one order and one charge (same `Idempotency-Key`, button disabled with "Processando"). Tested in Tasks 4 and 7.
5. **She changes the bag after starting payment and comes back to `/checkout/pagamento` by the browser history:** the order cookie is gone, so she lands on `/checkout` and must go through "Ir para pagamento" again, with the new total. Tested in Task 6.
