**Goal:** Have the bag working against the API: the panel that opens after "Adicionar à sacola" (`SAC-01`), the `/sacola` page (`SAC-02` to `SAC-16`) and quick buy from the product card (`CAT-08`).

**Architecture:** The API already calculates every amount (subtotal, discount, free shipping, shipping, total, installments, `canCheckout`); the front end only shows them. `cart/views.ts` turns the API `Cart` into the objects the screen uses; `/sacola` is a server page that reads the bag without cache and composes small client leaves (quantity, remove/undo, CEP and delivery, coupon, checkout button). Each leaf calls a Server Action that changes the bag in the API and ends with `refresh()` (decision of 2026-11-19, option A). The panel is a native `<dialog>`, opened with `showModal()`, so Esc, focus and the backdrop come from the browser.

**Tech Stack:** Next.js 16.4.6 (App Router, `cacheComponents` on), React 19 (`useActionState`), Tailwind 4, Zod 4, `server-only`, types generated by `openapi-typescript`, `node:test` and Playwright. No new dependency.

**Spec:** `docs/SPEC-CLIENT.md` (section 2, section 7 `SAC-01` to `SAC-16`, `CAT-08`, `PRO-07`, `GER-02`, `GER-06`, decision 19), `docs/DESIGN.md` (section 5, "Bag panel" and "Bag page"), `contract/openapi.yaml` (`getCart`, `addItem`, `updateQuantity`, `removeItem`, `setCartCep`, `chooseDelivery`, `applyCoupon`, `removeCoupon`), `docs/GLOSSARY.md`. Approved visual: the prototype at https://claude.ai/artifact/Tk4tUWmhrWb3WvRaZ97kHB (version 2).

## Global constraints

All the ones from the product page plan (`2026-11-18-product-page.md`) apply. In addition:

- **No contract change.** Everything the bag needs is already in `contract/openapi.yaml`.
- Amounts are never recalculated in the front end: show `subtotal`, `discount`, `amountToFreeShipping`, `deliveryOptions[].free`, `shippingAmount`, `total`, `installmentPlan` and `maxQuantity` as the API sends them.
- Bag authorization in every action: the cart id comes **only** from the cookie (`readCartId()`); `itemId` and `productSizeId` from the form are validated with `z.uuid()` and always go inside the path `/v1/carts/{cookie id}/...`, so an id from another cart answers 404.
- Every action ends with `refresh()` (from `next/cache`) after a change that worked, never after one that failed.
- `"use client"` only on the leaves listed in each task.
- Exact screen texts (Portuguese, as in the spec and the approved prototype): "Sua sacola", "Sua sacola está vazia", "As peças que você escolher aparecem aqui.", "Ver novidades", "Apenas N unidades restantes" / "Apenas 1 unidade restante", "Esgotada", "Esgotou depois que entrou na sacola. ## Review focus

1. **The API answers 409 when "+" is tapped** (stock dropped while the bag was open): the quantity stays as it was, the `problem.title` shows next to the item, and the page refreshes so the new `maxQuantity` and "Apenas N unidades restantes" appear. Tested in Task 4.
2. **"Desfazer" after the piece sold out:** `addItem` answers 409; the notice closes and "Não foi possível desfazer: {problem.title}" shows; no piece comes back. Tested in Task 4.
3. **Double tap on "+", "Aplicar" or "Finalizar compra":** the button is disabled while its action runs, so the quantity goes up by one only. Tested in Task 4.
4. **The bag cookie points to a cart the API no longer knows (404)** when she opens `/sacola`: she sees the empty bag (`SAC-03`), never an error. Tested in Task 3.
5. **Our API fails (500) on any bag action:** the `GER-06` message shows next to the control, the typed CEP or coupon stays in the field, and nothing else on the page changes. Tested in Tasks 5 and 6.
